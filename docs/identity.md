# BackupSAS Identity

BackupSAS identity is **not** a TLS certificate. Identity is an Ed25519 key pair with a ULID-prefixed participant ID.

## Participants

| ID prefix | Role |
|-----------|------|
| `sas_` | BackupSAS server |
| `cli_` | Backup client (any DBMS) |

Each participant has:

```
Identity
├── id          (sas_* or cli_*)
├── public_key  (32-byte Ed25519 verifying key)
├── secret_key  (never transmitted, never serialized in API)
└── fingerprint (SHA256 of public key, display only)
```

Wire format for public keys: `ed25519:<64 hex chars>`.

Fingerprints: `SHA256:AB:CD:EF:...` (uppercase hex pairs).

## Server identity

Created at `backupsas init`:

```
/var/lib/backupsas/identity/
├── identity.toml   # id + public_key
└── identity.key    # secret (mode 0600)
```

Operators register the server with clients using:

- `server_id` (e.g. `sas_01J...`)
- `public_key` (pinned)
- `fingerprint` (human verification)

Changing IP, DNS, or TLS certificate does not change identity. Changing `public_key` is a **hard reject** on the client.

## Client identity

Generated by the client (or operator). Stored in client config / vault. Used for:

- `HELLO` (public key in handshake)
- Proof-of-possession over server nonce
- Enrollment proof (if not yet trusted)

## Proof-of-possession

Every connection requires signatures over:

```
message = nonce || participant_id || timestamp_le_u64
signature = Ed25519_sign(secret_key, message)
```

Timestamps must be within ±300 seconds of server time.

Possession of a public key alone is insufficient; the peer must sign the current nonce.

## Trust pinning

Client `BackupSasConfig` pins:

```rust
server_id: ServerId,
server_public_key: PublicKey,  // must match HELLO_ACK
```

On mismatch: connection aborted with `TrustPinMismatch`.

## TLS vs identity

| Layer | Purpose |
|-------|---------|
| TLS 1.3 | Encrypt transport; server cert is dev/ops convenience |
| Ed25519 | BackupSAS authentication and authorization |

Compromised TLS cert without pinned identity key does not forge BackupSAS proofs.

## Secret key handling

- `SecretKey` is not `Serialize` / `Deserialize`
- `ZeroizeOnDrop`
- Access only via `Identity::sign()`
- Never logged, never in manifests, never sent to BackupSAS
